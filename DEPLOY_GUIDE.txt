================================================================================
   PORTFOLIO INFRASTRUCTURE — STEP-BY-STEP DEPLOYMENT GUIDE
================================================================================

This guide walks through deploying the portfolio from zero to a working website.


================================================================================
STEP 1: PREREQUISITES
================================================================================

1.1  AWS Account (free tier)
     - You should already have this from your Terraform learning
     - Make sure you have an IAM user with AdministratorAccess
       (or at minimum: EC2, VPC, S3, IAM, ELB permissions)

1.2  AWS CLI installed and configured
     $ aws --version        # Should show aws-cli/2.x
     $ aws configure        # Enter your access key, secret key, region=us-east-1

1.3  Terraform installed
     $ terraform --version  # Should show v1.x


================================================================================
STEP 2: UNDERSTAND WHAT YOU'RE BUILDING
================================================================================

Architecture:

  Internet → ALB (port 80) → EC2 instances (Nginx) → pulls content from S3

AWS resources Terraform will create:
  1. VPC (10.0.0.0/16) — your isolated network
  2. 2 public subnets (10.0.1.0/24, 10.0.2.0/24) across 2 AZs
  3. Internet Gateway — allows internet access
  4. Route table — routes 0.0.0.0/0 to IGW
  5. Security Group (ALB) — allows port 80 from internet
  6. Security Group (EC2) — allows port 80 from ALB SG only
  7. S3 bucket — stores website files
  8. IAM role + instance profile — lets EC2 read from S3
  9. Application Load Balancer — distributes traffic
  10. Target Group — health checks on port 80, path /
  11. Launch Template — defines EC2 config (AMI, type, user data)
  12. Auto Scaling Group — manages EC2 instances (min 1, max 2)

Total: ~15 AWS resources


================================================================================
STEP 3: DEPLOY THE INFRASTRUCTURE
================================================================================

3.1  Navigate to the terraform directory

     $ cd portfolio-infra/terraform

3.2  Initialize Terraform

     $ terraform init

     This downloads:
     - AWS provider plugin (~5.x)
     - terraform-aws-modules/vpc/aws module
     - terraform-aws-modules/alb/aws module

     You should see: "Terraform has been successfully initialized!"

3.3  Review the plan

     $ terraform plan

     Read through the output. You should see ~15 resources to create.
     Key things to verify:
     - VPC CIDR is 10.0.0.0/16
     - 2 subnets in us-east-1a and us-east-1b
     - ALB listener on port 80
     - ASG min=1, max=2
     - Launch template using t3.micro

3.4  Apply (create everything)

     $ terraform apply

     Type "yes" when prompted.

     This takes 3-5 minutes. The ALB takes the longest to create.

     When done, you'll see outputs like:
       website_url    = "http://shafi-portfolio-alb-123456.us-east-1.elb.amazonaws.com"
       s3_bucket_name = "shafi-portfolio-site-abc123"
       vpc_id         = "vpc-0abc123def456"

     SAVE the s3_bucket_name — you need it for the next step.


================================================================================
STEP 4: UPLOAD WEBSITE FILES
================================================================================

4.1  Upload to S3

     $ aws s3 sync ../website/ s3://$(terraform output -raw s3_bucket_name)/website/

     This uploads index.html and css/style.css to the S3 bucket.

4.2  Verify upload

     $ aws s3 ls s3://$(terraform output -raw s3_bucket_name)/website/ --recursive

     You should see:
       website/css/style.css
       website/index.html


================================================================================
STEP 5: WAIT FOR EC2 + HEALTH CHECKS
================================================================================

5.1  The EC2 instance launched during terraform apply. Its user data script:
     - Installs Nginx
     - Runs "aws s3 sync" to pull website files
     - Starts Nginx

5.2  The ALB health check needs to pass before traffic is routed.
     Health check: GET / on port 80, expects HTTP 200.
     This takes about 2-3 minutes after the instance is running.

5.3  If the instance launched BEFORE you uploaded files to S3:
     The user data has "|| true" so it won't fail — Nginx just serves
     the default page. To get the real content:

     Option A: Terminate the instance, ASG will launch a new one that
               pulls the latest from S3
     $ aws autoscaling set-desired-capacity \
         --auto-scaling-group-name $(terraform output -raw s3_bucket_name | sed 's/site//' | xargs -I{} echo "shafi-portfolio-") \
         --desired-capacity 0
     # Wait 30 seconds, then:
     $ aws autoscaling set-desired-capacity \
         --auto-scaling-group-name <ASG_NAME> \
         --desired-capacity 1

     Option B (simpler): Just destroy and re-apply after uploading to S3.


================================================================================
STEP 6: ACCESS YOUR WEBSITE
================================================================================

6.1  Get the URL

     $ terraform output website_url

     Open this URL in your browser. You should see your portfolio site.

6.2  If it shows "503 Service Temporarily Unavailable":
     - Health checks haven't passed yet. Wait 2-3 more minutes.
     - Check EC2 instance is running in AWS Console → EC2 → Instances
     - Check Target Group health in AWS Console → EC2 → Target Groups


================================================================================
STEP 7: VERIFY EVERYTHING WORKS
================================================================================

7.1  Check ALB is routing traffic:
     $ curl -s http://$(terraform output -raw s3_bucket_name | sed 's/site.*//; s/$/alb/')...
     Or just open the website_url in browser.

7.2  Check the EC2 instance:
     - AWS Console → EC2 → Instances → you should see 1 running instance
     - It should have tag: Name = shafi-portfolio-web

7.3  Check Target Group health:
     - AWS Console → EC2 → Target Groups → click the target group
     - Under "Targets" tab, instance should show "healthy"

7.4  Check S3 bucket:
     $ aws s3 ls s3://$(terraform output -raw s3_bucket_name)/website/


================================================================================
STEP 8: TAKE SCREENSHOTS (for resume/GitHub)
================================================================================

Take screenshots of:
  1. The portfolio website running in the browser (with ALB URL visible)
  2. AWS Console → VPC dashboard showing your VPC
  3. AWS Console → EC2 showing the running instance
  4. AWS Console → Load Balancer showing the ALB
  5. Terminal showing "terraform apply" output

These prove the project is real and actually deployed.


================================================================================
STEP 9: DESTROY (IMPORTANT — AVOID CHARGES)
================================================================================

9.1  Destroy all resources

     $ cd portfolio-infra/terraform
     $ terraform destroy

     Type "yes" when prompted.

     This deletes EVERYTHING: VPC, subnets, ALB, EC2, S3, IAM role.

9.2  Verify in AWS Console that no resources remain.
     Specifically check:
     - EC2 → Instances (should be empty or terminated)
     - EC2 → Load Balancers (should be empty)
     - VPC → Your VPCs (only default VPC should remain)
     - S3 → Buckets (the portfolio bucket should be gone)

9.3  The ALB is the main cost (~$16/month). As long as you destroy
     after testing, you'll only pay pennies.


================================================================================
STEP 10: PUSH TO GITHUB
================================================================================

10.1  Create a new GitHub repo called "portfolio-infra"
      (or whatever name you prefer)

10.2  Push the code

      $ cd portfolio-infra
      $ git init
      $ git add .
      $ git commit -m "AWS portfolio infrastructure with Terraform"
      $ git remote add origin https://github.com/mohamedshafims/portfolio-infra.git
      $ git push -u origin main

10.3  The .gitignore ensures terraform.tfstate, .terraform/, and
      terraform.tfvars are NOT pushed (security).

10.4  Set up GitHub Secrets for CI/CD (optional):
      - Repo → Settings → Secrets and variables → Actions
      - Add secret: AWS_ACCESS_KEY_ID
      - Add secret: AWS_SECRET_ACCESS_KEY
      - Add variable: S3_BUCKET_NAME (from terraform output)
